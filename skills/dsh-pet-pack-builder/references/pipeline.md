# 处理管线：每一步为什么这么写

这份文档记录的是实测过的结论。改代码前先读，避免把已经踩平的坑再踩一遍。

## 全流程

```
mp4 (绿幕) 
  → ffmpeg 解成 rgb24 帧
  → keyer.key_frame()      抠像：绿幕 → alpha，去阴影 / 水印 / 绿溢
  → pad_to_16x9()          补透明边（仅比例不对时）
  → encode.bleed()         颜色外渗：把角色颜色糊进透明区
  → VP9 yuva420p 编码        →  xxx.webm
```

## 1. 抠像为什么用「饱和度」当主判据

背景是低饱和灰绿（色相 100~165°，饱和度 0.1~0.4），角色是粉发 / 白衣 / 蓝眼。
两者的**饱和度分布**重叠很小，而色相分布由于低饱和像素色相不稳定，反而不可靠。

所以判定是 `sat >= sat_min & hue ∈ [lo, hi] & val >= val_min`：

- 白衣服 sat ≈ 0.02~0.05 → 不会被吃（这条最关键）
- 粉头发 hue ≈ 340~360 → 被色相护栏挡住
- 蓝眼睛 hue ≈ 210~230 → 同理

色相窗口（默认 60~188°）只当护栏用，不需要精确——这是刻意的设计：
把色相当主判据会在暗部翻车（见下一条）。

## 2. 地面阴影：暗部色相会漂

绿幕上的地面投影被压暗后，色相从 130° 漂到 180~210°（偏青），饱和度也降了。
原来的绿区规则只给这种像素半透明 alpha，结果角色脚下留一圈**灰蓝色雾**。

修法：单独一条规则，只在画面下方 `floor_y` 以下、且远离角色主体的区域，
把 `hue ∈ [148, 218] & sat >= 0.12 & val < 0.80` 直接判透明。

## 3. core 掩膜必须拆成两个

原本一个「角色主体膨胀 11px」的掩膜同时干两件事：豁免阴影清理、强制不透明。
这导致带绿溢的那圈描边被锁成不透明，**去溢色的条件（alpha < 0.98）永远够不到它**——
绿边被保护了起来。

现在拆成：

- `guard`（膨胀 11px）：只用于「阴影 / 水印清理别误伤角色」
- `solid`（膨胀 2px）：只用于强制 alpha = 1，防止头发裙子里被误挖洞

原则：**保护范围必须小于要修的范围**，否则修复会被自己豁免。

另外 `guard` 的种子必须排除「暗青」像素和水印像素，否则残留阴影会把自己认成主体而自我豁免。

## 4. 绿溢必须按几何距离判定

实测：绿幕混色向角色轮廓内侧渗透约 3px。

| 距轮廓 | 1px | 2px | 3px | 4px |
|---|---|---|---|---|
| 绿溢值 g−(r+b)/2 | +26 | +17 | +5.5 | ≈0 |

这些像素是**不透明**的，用 alpha 阈值判定边缘根本选不中它们。正确做法：

```python
outside = (alpha < 0.02)                      # 透明区
frac = box_blur(outside, RIM_PX)              # 用模糊近似「离轮廓多远」
w = clip(frac * 2.6, 0, 1)                    # 越靠外权重越大
g -= w * max(0, g - max(r, b))                # 只削超出部分，不动正常颜色
```

效果：主体区绿溢 p99 从 29.5 → 1.5，绿溢 >8 的像素从 5.4% → 0.1%。

## 5. 颜色外渗：只写透明区

VP9 的 alpha 是 4:2:0，**色度平面不带 alpha**，会跟邻近透明像素做平均。
透明区如果留黑或绿幕色，轮廓外必然混出一圈暗边 / 绿边。

正确写法是加权扩散：

```python
acc = rgb * a;  w = a
重复 N 次：acc = blur(acc); w = blur(w)
filled = acc / max(w, 1e-3)
```

**坑**：不透明区 `a ≡ 1`，此时 `blur(rgb*a)/blur(1) = blur(rgb)`，
等于把整张图过了一遍高斯模糊。实测角色内部梯度能量 11.69 → 4.96，**细节掉 58%**。
这是「成品发虚」的真正原因，不是分辨率问题。

所以必须混回去：`a >= 0.72` 用原值，`a <= 0.12` 用外渗值，中间线性过渡。

## 6. 分辨率：不要缩

| 版本 | 清晰度保留率（显示宽 500px 下相对无损帧） | 体积 |
|---|---|---|
| 640×360 crf30 | 42.0% | 4.6 MB |
| 1280×720 crf20 | 92~99% | 19.8 MB |

同样分辨率下 crf 16/20/24/30 的梯度差 < 0.5%，所以先保分辨率再谈 crf。
浏览器把 720p 下采样到 500px 是「减采样」，边缘比原素材还锐。

## 7. 水印

AI 生成素材右下角常有「豆包AI生成」白字。内置 `assets/wm_mask_1280x720.npz`
是从官方 `watermark_mask_v5.mkv` 取一帧、去底边噪声、膨胀 2px 得到的逐像素遮罩
（bbox x 1066~1244 / y 638~682），已逐帧确认与角色像素**零重叠**。

载入时再膨胀 3px：水印字形的抗锯齿边缘饱和度刚好卡在 `sat_min` 之上，
不膨胀会在右下角留一小片灰斑（实测 567 个像素）。

### 残影为什么会「闪」

只膨胀遮罩是不够的。遮罩之外的边缘像素仍然是「亮、低饱和」，抠像不会把它们判成背景，
于是它们变成**不透明像素 → 成为角色种子 → 给自己撑起 guard/solid 保护圈**。
保护圈一旦存在，`wm & ~guard` 就放过了旁边的遮罩像素；下一帧这些边缘像素的亮度/饱和度随编码抖动，
保护圈跟着变，残影就一亮一灭——表现就是「右下角有东西在闪」。

所以顺序必须是：

1. 水印区（遮罩 + 20px 余量）里「灰白/发绿」的东西不许当种子；
2. 最后再补一刀，把「薄 + 灰白或发绿」的像素 alpha 归零——**这一刀要放在 solid 之后**，
   否则会被「内芯强制不透明」重新提起来，白改。

判据用「绿偏色」而不是 HSV 饱和度：这些像素是绿幕上压白字，HSV 饱和度只有 0.07~0.09，
但 G 比 R/B 高 15~25，用 `g > r+6 and g > b+6` 才抓得住。

保护真正的白色物体（白衣服、水晶镜框）靠 `thick`：把不透明掩膜腐蚀 12px 再膨胀回来，
只有厚度 ~25px 以上的结构才算「实体」，字形笔画 4~6px 整条被筛掉。

`thick` **必须用去完阴影之后的 alpha 算**：地面投影是一整片不透明，算进去的话整个画面下沿
都被判成实体，宏块级的灰绿噪声反而清不掉（实测「睡觉」第 12 帧一整块 20×30 的灰块漏网）。

画面最外一圈（24px）另外无条件清：AI 视频偶尔整块宏块闪灰绿，那种块又方又厚，
会骗过 `thick`。这一圈本来就是背景，清掉不会伤到角色。

实测（待机 97 帧，右下角 280×120 区域）：残留帧 12 → 0，闪烁像素 949 → 0，峰值标准差 50.7 → 0；
「睡觉」「点击」「思考」「问侯」同区域也降到 0。

## 8. 验证手段的坑

- **ffmpeg 4.1 解 VP9 alpha 一律返回 255**，不能用来判断有没有透明通道。
  只能看 `ffmpeg -i` 输出里的 `alpha_mode: 1`，或用 Chromium 实际渲染。
- **不要用 PSNR 对比「keyed 参考帧」**：参考帧把半透明区与白底合成过，解码帧不会，
  会得到 15dB 的假低值。用**梯度能量比**。
- **判断边缘是否干净要把画面叠在品红上**。棋盘格会把半透明灰边伪装成正常过渡。
- 顺带：`yuva420p` 的颜色范围往返没问题（实测 200,120,90 → 199,118,89），
  不要乱加 `-color_range`。

## 9. 半透明道具：伞面、泡泡、镜子

绿幕透过塑料/玻璃时，透过率决定了「绿」剩多少。同一个材质在不同区域厚度不同，
绿色残留量就不同，于是出现两类完全不同的失败：

### 9.1 灰绿「脏块」（`--deglass`）

伞面、泡泡上那种一块块的脏污，本质是**绿幕透了 20~35% 进来**。它不是饱和的绿，
HSV 饱和度只有 0.10~0.13，`sat_min`（0.085）勉强够不到，于是被当成前景留下。

判据要用「绿偏色」而不是饱和度：

```
(g > r + 7) & (g > b + 7) & (sat < 0.13) & (val > 0.42)  →  alpha = 0
```

颜色不能顺手压掉——直接削 G 会把伞面变成死灰色。正确做法是 alpha 归零，
让第 5 节的 `bleed()` 用周围真正的塑料色填进去，视觉上才是「透明塑料」而不是「脏」。

保守起见 `--deglass` 只对指定的片段生效（`--clips 乘伞滑行 梦境泡泡 --deglass`），
不要全局开：白色衣服在阴天光下也可能落进这个窗口。

### 9.2 镜面被抠成空心框（`glass_prop.py`）

镜子的情况更绝：玻璃后面**整片都是绿幕**，所以抠完只剩镜框和一缕半透明倒影，
中间是空的。这不是参数问题，是信息缺失——玻璃后面的东西没被拍下来，无法还原，只能重建。

做法分四步，区域**只标定一次**（机位静止，逐帧复用）：

1. 镜框是不透明闭合轮廓 → 形态学闭运算（半径约 26px）补上镜框的细缝/高光缺口；
2. `fill_holes` 从画面边界 flood fill，填不到的就是镜面内部 → 得到整块镜面区域；
3. `region &= ~opaque` 只填透明部分，镜框和倒影不参与；
4. 每帧在区域里垫一层浅蓝白磨砂玻璃（`--glass-alpha`，默认 0.72），
   区域内的绿色判为背景清掉、粉/白倒影原样保留。

**合成时必须除以最终 alpha。** WebM 存的是直通（straight）alpha，而

```
out_rgb = fg*fa + glass*ga*(1-fa)
out_a   = fa + ga*(1-fa)
```

算出来的是**预乘**值；直接用会让玻璃被自己的不透明度压暗——`ga=0.55` 只剩 45% 亮度，
深色壁纸上看就是一片灰。正确写法：

```
out_rgb = (fg*fa + glass*ga*(1-fa)) / max(out_a, 1e-3)
```

这也是默认值从 0.55 提到 0.72 的原因：修好除法后 0.55 偏透，0.72 才像一块正常玻璃。
放在深色壁纸上仍嫌亮的话，往下调到 0.6 左右。

## 10. 青色小件：玩偶眼睛为什么会被抠掉

绿幕判定是「色相窗口 + 饱和度下限」，窗口开到 60~188° 是为了照顾绿幕的宽色散
（实测不同素材的背景色相从中位 99° 一直漂到 156°）。代价是**青色也落进窗口**：
角色怀里玩偶的眼睛常画成薄荷绿，实测 RGB 141,183,179 → 色相 175°、饱和度 0.14，
两条判据都满足，于是被当成背景，成品里就是一个能看见背后内容的透明小洞。

这类像素没法靠「收窄色相窗口」解决：窗口上界一旦压到 175° 以下，色相 156° 的那批素材
（背景本身就偏青）就会在边缘掉一圈。只能单独识别、单独救回。

### 判据为什么需要两条证据

- **颜色偏青**：绿幕是黄绿，蓝远低于绿（背景 `b-g` 中位 -35、99.9 分位也只到 +18~31）；
  青色件 `b-g ≈ -4`。用 `b >= g-12 & g > r+10 & g > 120` 能分开。
- **周围一圈不透明**：光看颜色会翻车——「摘星星」那段背景色相 156°，单帧有 4500 个背景像素
  满足上面的颜色判据。加一条「半径 14px 内不透明像素 ≥78%」就干净了：
  玩偶眼睛在角色内部，环形占比 0.90；背景即使贴着角色轮廓也只有 0.5 上下。

实测（13 段各取 1 帧）：每段救回 98~233 个像素，全部集中在玩偶眼睛处，背景零误保护。
耗时增加约一次 `box_blur`，单帧 ~5%。

### 顺序

必须放在**所有抠除动作之后**（阴影、水印、软阈值、solid），否则会被后面的清除再抹掉一次。
放在 `solid` 之前也不行：眼睛只有 14×7px，`core_force=2` 的内芯撑不起来。
